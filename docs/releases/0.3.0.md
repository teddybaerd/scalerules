# ScaleRules 0.3.0

## English

- Extend exit-node failover to three prioritized nodes: primary → optional secondary → final backup. Existing two-node configurations remain compatible.
- Automatically select the highest-priority confirmed reachable node. Outage switching and automatic return now use the same configured waiting period and confirmation probe count.
- Check the configured DNS resolver after automatic switches without reconnecting the VPN or overriding DNS settings. Fix stale health warnings when the VPN engine reports a healthy state without a warning map, including recovery through an unknown intermediate state.
- Add a dedicated **Settings → Exit-node failover** page with clearly labeled selection fields and Beta wording. Rule automation and failover share the same start/pause controls.
- Show the correct Connection rules page header and direct **Report a bug** to ScaleRules GitHub Issues.

**Device validation:** The maintainer tested 0.2.10-rc.2 and confirmed the expected failover behavior, suitable return timing, and automatic disappearance of intermittent DNS warnings without reconnecting. Earlier three-node RC1 testing covered failures and recoveries in different orders; RC2 was tested after the DNS and timing fixes.

**Known limits:** A DNS warning may still briefly appear and clear automatically. DNS checks run after automatic switches, not as continuous internet-health monitoring. Peer-online status can be delayed; reachability does not guarantee working internet forwarding. DNS must remain reachable when a home site fails. If all configured nodes fail, the VPN remains enabled. Existing split-tunnel exclusions and Android background restrictions still apply.

**Installation:** Install `scalerules-0.3.0.apk` over the existing permanently signed ScaleRules app, including 0.2.9 or 0.2.10-rc.2. Do not uninstall first; accounts, rules and settings are retained. The secondary node is optional and can be selected under **Settings → Exit-node failover**.

## Deutsch

- Exit-Node-Failover auf drei priorisierte Knoten erweitert: Hauptknoten → optionaler zweiter Knoten → letzter Ersatzknoten. Bestehende Konfigurationen mit zwei Knoten bleiben kompatibel.
- Automatischer Wechsel zum höchstpriorisierten, bestätigt erreichbaren Knoten. Ausweichen und automatische Rückkehr verwenden jetzt dieselbe eingestellte Wartezeit und Anzahl von Bestätigungsprüfungen.
- Den konfigurierten DNS-Resolver nach automatischen Wechseln prüfen, ohne den VPN neu zu verbinden oder DNS-Einstellungen zu überschreiben. Veraltete Zustandswarnungen werden bei einer gesunden Rückmeldung ohne Warnungsliste entfernt, auch nach einem zwischenzeitlich unbekannten Zustand.
- Eigene Seite **Einstellungen → Exit-Node-Failover** mit klar beschrifteten Auswahlfeldern und Beta-Kennzeichnung. Regelautomatik und Failover verwenden gemeinsame Start-/Pause-Steuerung.
- Korrekter Seitentitel für Verbindungsregeln; **Fehler melden** führt zu den GitHub-Issues von ScaleRules.

**Gerätetest:** Der Maintainer hat 0.2.10-rc.2 getestet und das erwartete Failover-Verhalten, passende Rückkehrzeiten sowie das selbstständige Verschwinden gelegentlicher DNS-Warnungen ohne Reconnect bestätigt. Frühere Tests mit RC1 deckten Ausfälle und Rückkehr verschiedener Knotenreihenfolgen ab; RC2 wurde nach den DNS- und Zeitkorrekturen getestet.

**Bekannte Grenzen:** Eine DNS-Warnung kann weiterhin kurzzeitig erscheinen und von selbst verschwinden. DNS wird nach automatischen Wechseln geprüft; eine kontinuierliche Internet-Funktionsprüfung findet nicht statt. Online-Meldungen können verzögert eintreffen; Erreichbarkeit bestätigt keine funktionierende Internetweiterleitung. DNS muss auch bei Ausfall eines Heimstandorts erreichbar bleiben. Bei Ausfall aller konfigurierten Knoten bleibt der VPN aktiviert. Bestehende Split-Tunnel-Ausnahmen und Android-Hintergrundbeschränkungen gelten weiterhin.

**Installation:** `scalerules-0.3.0.apk` über die bestehende dauerhaft signierte ScaleRules-App installieren, auch über 0.2.9 oder 0.2.10-rc.2. Nicht vorher deinstallieren; Konten, Regeln und Einstellungen bleiben erhalten. Der zweite Knoten ist optional und lässt sich unter **Einstellungen → Exit-Node-Failover** auswählen.
