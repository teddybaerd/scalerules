## English

- Add optional exit-node failover with a preferred and backup node in the same account. Existing online-status events trigger bounded reachability checks; healthy operation adds no periodic pings.
- Confirm an outage before switching and optionally return after a configurable confirmation delay. Failover is disabled by default; configure it in **Settings → Connection rules**, select the preferred node and resume automation.
- Resume previously active rule automation after app updates, independently of the reboot setting. Deliberately paused automation stays paused. Missing permissions or blocked foreground startup produce a recovery notification when notifications are allowed. Saved settings remain intact and current connection rules are evaluated again.
- Fix monitoring of offline nodes whose exit routes disappear, prevent capability-only network updates from resetting the grace period, and add decision-journal diagnostics.
- Include reviewed Mockito and Kotlin OTP dependency updates. The Vico 3 migration remains deferred.

**Validation:** Android builds, unit tests, formatting, Go tests, lint, signing checks and security monitoring passed. Device tests of 0.2.9-rc.2 confirmed switching to the VPS, website access through the backup, automatic return, and both switches with the display locked. Update recovery is new and has automated policy coverage; device installation validation remains pending.

**Limits:** Peer-online events may be delayed. Reachability does not guarantee working internet forwarding or DNS. DNS must remain available if the preferred site fails. If both nodes fail, failover does not disable the VPN. Existing split-tunnel exclusions still apply. Android background restrictions may delay operation.

**Installation:** Install `scalerules-0.2.9.apk` over the existing signed app; do not uninstall. Leave automation active before updating to check automatic recovery. Required Android permissions and background-operation settings still apply.

## Deutsch

- Optionales Exit-Node-Failover mit Haupt- und Ersatzknoten desselben Kontos ergänzt. Vorhandene Online-Statusmeldungen lösen begrenzte Erreichbarkeitsprüfungen aus; im normalen Betrieb gibt es keine regelmäßigen zusätzlichen Pings.
- Bestätigte Umschaltung bei Ausfall und auf Wunsch verzögerte automatische Rückkehr. Standardmäßig ausgeschaltet: unter **Einstellungen → Verbindungsregeln** einrichten, Hauptknoten auswählen und Automatik starten.
- Zuvor aktive Regelautomatik nach App-Updates automatisch fortsetzen, unabhängig vom Geräteneustart-Schalter. Bewusst pausierte Automatik bleibt pausiert. Bei fehlenden Berechtigungen oder blockiertem Hintergrundstart erscheint bei erlaubten Benachrichtigungen ein Hinweis zum Fortsetzen. Gespeicherte Einstellungen bleiben erhalten; aktuelle Verbindungsregeln werden neu ausgewertet.
- Überwachung ausgefallener Knoten auch ohne gemeldete Exit-Routen korrigiert, wiederholtes Zurücksetzen der Schonfrist durch reine Netzwerk-Statusaktualisierungen verhindert und Diagnoseeinträge ergänzt.
- Geprüfte Mockito- und Kotlin-OTP-Abhängigkeitsupdates übernommen. Die Vico-3-Migration bleibt zurückgestellt.

**Prüfung:** Automatische Builds, Unit-Tests, Formatierung, Go-Tests, Lint-, Signatur- und Sicherheitsprüfungen erfolgreich. Gerätetests mit 0.2.9-rc.2 bestätigten Hin- und Rückwechsel, Webseitenzugriff über den Ersatzknoten und beide Wechsel bei gesperrtem Display. Das neue Fortsetzen nach Updates ist automatisiert geprüft; die Installation auf einem Gerät steht noch aus.

**Grenzen:** Online-Meldungen können verzögert eintreffen. Erreichbarkeit bestätigt keine funktionierende Internetweiterleitung oder DNS-Auflösung. DNS muss unabhängig vom ausgefallenen Hauptstandort erreichbar bleiben. Sind beide Knoten ausgefallen, schaltet Failover den VPN nicht ab. Bestehende Split-Tunnel-Ausnahmen gelten weiterhin. Android-Hintergrundbeschränkungen können den Ablauf verzögern.

**Installation:** `scalerules-0.2.9.apk` über die bestehende signierte App installieren, nicht vorher deinstallieren. Automatik vor dem Update aktiv lassen, um das automatische Fortsetzen zu prüfen. Erforderliche Android-Berechtigungen und Einstellungen zum Hintergrundbetrieb gelten weiterhin.
