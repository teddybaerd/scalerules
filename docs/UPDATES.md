# ScaleRules app updates

ScaleRules checks the public GitHub Releases API for the latest **stable** release.
Checks run when opening the app, at most once every 24 hours. There is no background
polling service. GitHub receives the normal HTTPS request (including the client IP);
no account, rules, SSIDs or device identifiers are sent.

Under **Settings → App updates**, users can turn automatic checks off, check manually,
read the release notes and download an APK. GitHub downloads and Obtainium remain
available independently. A manual check also shows a previously skipped version.
“Later” postpones automatic prompts for 24 hours; “Skip this version” suppresses that
tag only. Network errors during an automatic check do not interrupt VPN operation.

Downloads are limited to 150 MiB, use HTTPS and follow redirects only to GitHub's
approved asset hosts. Before offering an APK to Android, ScaleRules checks:

- GitHub's asset SHA-256 digest and exact byte size;
- the installed package identity;
- a strictly newer Android versionCode and the expected stable versionName;
- the same current signing certificate(s) as the installed app;
- a non-debuggable APK.

The APK remains in private cache storage and is shared read-only through a narrow
FileProvider path. Android performs final signature verification and prompts the
user to install. If necessary, users first allow installation from ScaleRules in
Android settings, return and tap **Install update** again. No silent installs.
The file is verified again immediately before opening the installer.

## Publishing compatible releases

The updater requires an actual public GitHub Release with:

1. A stable semantic tag such as `v0.2.0` (no draft or prerelease).
2. Exactly one asset named `scalerules-0.2.0.apk`, matching the tag without `v`.
3. GitHub's `sha256:…` asset digest (generated by GitHub after upload).
4. A release body containing the changelog; currently rendered as plain text.
5. A release APK built by **Signed APK** with version `0.2.0` and the permanent key.

Publish the APK itself, not only the workflow artifact ZIP. Include SHA256SUMS,
build-info.json and signing-certificate-sha256.txt from the signed artifact for
independent verification. A workflow artifact alone is deliberately not an update
source. Production signing secrets stay exclusively in `release-signing`.

The installed `0.1.0` does not yet contain this updater. Install `0.2.0` manually over
it once; test that Headscale configuration and rules remain intact. After publishing
another signed release (for example `0.2.1`), test the complete in-app path, including
Later, Skip, disabled checks, installer cancellation, wrong hash/signer rejection,
and recovery after a failed download. Never use a debug APK to update the signed app.
